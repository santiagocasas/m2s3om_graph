**1. `web/src/curation.js` (NEW module — the session-only store + `/suggest` client)**

Create a new module that owns ALL curation state and the `/suggest` fetch. Per D-06 (one-way constraint), this module MUST NOT touch SurrealDB, `localStorage`, `sessionStorage`, or `IndexedDB`. The ONLY storage is a module-scope `Map`.

Exports and internal shape:

- Module-private `const decisions = new Map();` — keyed by `${crosswalkId}::${sourceField}::${targetPath}`, value `{ status: 'accepted' | 'rejected', candidate: CandidateRule, crosswalkId, sourceField, decidedAt: Date }`. `targetPath` may be `null` (D-05 allows null); use the literal string `'null'` in the key when so.
- Module-private helper `function decisionKey(crosswalkId, sourceField, targetPath)` returning the string above.
- `export function getSuggestApiUrl()` — returns `import.meta.env.VITE_SUGGEST_API_URL || 'http://localhost:8000/suggest'`. This is the ONLY place the URL is resolved. Do NOT hardcode a production Pages/Space origin (D-04; RESEARCH from Phase 03 D-05 left the production URL unresolved).
- `export async function postSuggestRequest({ sourceStandard, targetStandard, sourceField, targetSchemaFields, context })` — POSTs `{ source_standard, target_standard, source_field, target_schema_fields, context }` (snake_case per D-03) as JSON to `getSuggestApiUrl()`, with header `Content-Type: application/json`. On non-2xx, throw `new Error(\`Suggestion request failed: ${response.status} ${response.statusText}\`)`. On network failure (fetch rejects), rethrow with `new Error(\`Suggestion request failed: ${err.message}\`)`. Return the parsed JSON body (`CandidateRule[]`). Do NOT catch-and-swallow; the caller renders the error message inline.
- `export function acceptCandidate(crosswalkId, sourceField, candidate)` — writes `{ status: 'accepted', candidate, crosswalkId, sourceField, decidedAt: new Date() }` to `decisions` under the computed key. Overwrites any prior decision for the same (crosswalk, source_field, target_path) — Accept replaces Reject and vice versa (implements CUR-02 "mark each candidate as accepted or rejected" — last write wins per candidate).
- `export function rejectCandidate(crosswalkId, sourceField, candidate)` — same shape with `status: 'rejected'`.
- `export function getDecision(crosswalkId, sourceField, candidate)` — returns the stored record or `undefined`.
- `export function getAcceptedCandidates()` — returns an array of `{ crosswalkId, sourceField, candidate, decidedAt }` for every `status === 'accepted'` entry, in insertion order (Plan 02 consumes this for TSV export). Also `export function getRejectedCandidates()` symmetric to the above (used for parity + testability; Plan 02 may or may not surface it).
- Do NOT export `decisions` directly; keep it module-private. Do NOT add a `clearDecisions()` unless Plan 02 needs it.

**Forbidden inside `curation.js`:** any import from `surrealdb` / `@surrealdb/wasm`, any reference to `localStorage`, `sessionStorage`, `indexedDB`, `indxdb://`, or `document.cookie`. The module MUST be pure JS state + one `fetch()` call. This is the D-06 boundary and is grep-enforced by the smoke test in Task 2.
