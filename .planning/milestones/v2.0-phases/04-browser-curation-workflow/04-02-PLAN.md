**1. `web/src/curation.js` — append two exports and one private helper**

- Add a private helper `function sanitizeTsvField(value)`:
  - If `value == null` (null or undefined), return `''`.
  - Otherwise, `return String(value).replace(/[\t\r\n]/g, ' ')` — collapses embedded delimiters to a single space so the TSV stays one-row-per-record.
- Add `export function buildAcceptedTsv()`:
  - Emit the header row: `'source_standard\tsource_field\ttarget_path\tmapping_type\tconfidence\tevidence\tnotes\n'`.
  - For each `entry` from `getAcceptedCandidates()` (already returns `{crosswalkId, sourceField, candidate, decidedAt}`), emit one data row:
    - `source_standard` derivation: the `crosswalkId` in this project follows the shape `{source}_to_{target}` (e.g. `datacite_to_dc`, `datacite44_to_dcterms`). Compute `const sourceStandard = String(crosswalkId).split('_to_')[0]`. If the split yields the original string unchanged (unexpected shape), fall back to the raw `crosswalkId` and continue — do NOT throw; TSV export must be resilient to unknown crosswalk id shapes.
    - `source_field` = `entry.sourceField`.
    - `target_path` = `entry.candidate.target_path` (may be `null` per D-05 → `sanitizeTsvField` handles that as empty).
    - `mapping_type` = `entry.candidate.mapping_type`.
    - `confidence` = `entry.candidate.confidence` (a number; `String(0.95)` → `'0.95'`; do not `.toFixed()` — preserve the model's precision).
    - `evidence` = `entry.candidate.evidence`.
    - `notes` = `entry.candidate.notes` (optional per D-05).
    - Join the seven fields with `'\t'` and terminate with `'\n'`.
  - Concatenate and return the full string.
- Add `export function downloadAcceptedTsv(filenameOverride)`:
  - `const filename = filenameOverride || 'accepted_candidates.tsv';` — D-07 fixes the default filename; the override is purely for testing / future extension.
  - `const tsv = buildAcceptedTsv();`
  - `const blob = new Blob([tsv], { type: 'text/tab-separated-values;charset=utf-8' });`
  - `const url = URL.createObjectURL(blob);`
  - Create an `<a>` element with `href=url`, `download=filename`, append to `document.body`, `.click()` it, then remove it and call `URL.revokeObjectURL(url)`.
  - Return `filename` for testability.
- Do NOT introduce any persistence: no `localStorage`, no server upload, no writing back to SurrealDB. The Blob lives in memory and is discarded after download.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| In-memory decisions → downloaded TSV file | Curator's accepted-candidate memory crosses out of the browser via `Blob` + object URL. |
| Object URL lifetime → browser memory | An un-revoked object URL leaks the underlying Blob into browser memory. |
| Notice copy → curator understanding | The UI copy IS the contract that "no automatic write-back" is happening; if it is wrong or missing, the curator may build the wrong mental model. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Injection (TSV formula / field escaping) | `buildAcceptedTsv` | medium | mitigate | Task 1 requires `sanitizeTsvField` to strip `\t\r\n` from every value; the header is a fixed literal. This prevents an LLM-returned `evidence` or `notes` string from breaking the row/column structure. Formula-injection (leading `=`, `+`, `-`, `@` triggering spreadsheet formulas on open) is scoped out — the file is `.tsv` (not `.csv`) and downstream tooling for the SSSOM merge is not a spreadsheet. |
| T-04-07 | Information Disclosure | Object-URL leak keeps Blob resident | low | mitigate | Task 1 requires `URL.revokeObjectURL` immediately after the `<a>.click()`; grep-enforced by Task 2. |
| T-04-08 | Repudiation / UX Contract | Missing / rewritten no-write-back notice | high | mitigate | Task 2 grep-locks three key substrings of the notice copy in `web/index.html`. Any future edit that removes or paraphrases the "the explorer never writes back" clause fails CI. This is the D-06/D-07 UI contract. |
| T-04-09 | Tampering | Persistence sneaking into `curation.js` under the guise of TSV plumbing | high | mitigate | Task 2 re-runs the Plan 01 D-06 negative regex against `curation.js` after Plan 02 changes — belt-and-braces to catch a well-intentioned "let's cache the accepted set" refactor. |
</threat_model>
